# RoadPulse

An original, community-driven navigation app for Android, built on open data and open-source
components. "RoadPulse" is a placeholder name; check trademark availability before launch.

## What works today (v0.1 scaffold)

- Modern map-first layout: floating search panel (Explore), route card with "Go now" (Preview),
  and a dark driving view with a big turn card, turn arrows, a "Then …" hint for close turns,
  a speed ring, a trip panel with arrival time and progress, and quick mute/report buttons
  (`docs/screenshots/overlays-part-a.png`)
- Vector map (MapLibre + OpenStreetMap tiles) with the user's live location
- Destination search (Photon geocoder)
- Route calculation and drawing (Valhalla), with distance and ETA
- Navigation mode: camera follows the driver, banner with the next instruction and distance
  to the turn, live remaining time and arrival time, automatic rerouting, arrival detection
- Voice guidance (device text-to-speech): a heads-up about 500 m before each turn and the
  full instruction at the turn; turns less than 150 m apart are announced together ("…, then turn
  left" / "…, kemudian belok kiri"). Music lowers its volume during prompts (audio ducking), and a
  Mute button in the navigation banner is remembered across restarts. Voice and banner in
  English, Bahasa Melayu or Arabic (settings button on the search bar). Malay and Arabic
  instructions are generated by the app (the routing server has neither); review sheets:
  `docs/MALAY_PROMPTS.md`, `docs/ARABIC_PROMPTS.md`. Choosing Arabic also shows every screen in
  Arabic, laid out right to left (`app/.../i18n/Strings.kt`, review sheet `docs/ARABIC_SCREENS.md`).
  Malay screens are not translated yet (voice is Malay, screens English)
- Lane arrows before turns and exits (lane data from the map), an Overview button while driving,
  school zone warnings (spoken and shown; not on expressways), and "Open now / closes 22:00" in
  fuel, food and parking lists (from OpenStreetMap opening hours)
- Leave later: plan a drive with an arrive-by time (today or tomorrow); a "Time to leave" reminder
  comes 5 minutes before the leave time (travel time + 10 min spare). Stored on the phone only
- Music controls while driving (play/pause/next for Spotify, YouTube Music...), opt-in in Settings;
  needs Android notification access, used only to see which music is playing
- Profile with points, levels and badges for reporting (anonymous, optional nickname)
- Share my drive: a preview of what the link shows, then a live link with arrival time and
  position; the driver sees how many people are watching (works on the laptop now; for everyone
  once the server is online)
- Route choices on the map or as a list (arrival time with traffic, traffic bar, toll, Go); while
  driving, pull up the trip card for the route with traffic, other routes, share and stop
- Driving map: traffic colours on the route line, the next turn and its road name on the map,
  compass top left
- Search: nearby results first with the distance on each; "Add a missing place" (press and hold the
  map) for shops, clinics, entrances… search does not know: the driver finds it at once, everyone
  after a moderator approves it (admin page, New places tab)
- Menu: profile, planned drives, settings grouped in pages (General, Map display, Voice and sound,
  Navigation, Vehicle, Alerts and reports, Speedometer, Privacy), help and feedback
- Live traffic (opt-in, anonymous, ADR 0004): slow and jammed roads on the map
- Privacy: policy, export and delete my data (server and phone), consent before live traffic,
  retention limits
- Traffic: automatic jam reports from live traffic; arrival time includes traffic delay; a faster
  route around jams is offered during the drive (Take it / No thanks)
- iPhone app: shared Kotlin logic in `shared/`, Swift app in `iosApp/`; reaches the laptop servers over Wi-Fi (`backend/open-iphone-access.ps1`), see `docs/IOS.md`
- Testing on a real phone (iPhone and Android): step-by-step checklist in `docs/PHONE-TEST.md`
- Toll estimates on route cards from a price table you maintain (`backend/tolls/`)
- Real phone over USB with everything on the laptop: `connect-phone.bat`, `docs/REAL_PHONE.md`
- Navigation keeps running in the background and with the screen off (foreground service
  with an ongoing notification and a Stop action)
- Survives interruptions: the active drive is saved and resumes if Android stops the app;
  "GPS signal lost" and "Offline: keeping your current route" states instead of silence.
  See `docs/OFFLINE.md` for exactly what works without network or GPS
- Speed-limit sign next to the speed ring where OpenStreetMap has a limit (80-88% of tested KL
  routes); the ring scales to the limit and turns red above it
- Home and Work shortcuts and recent destinations in the search panel (tap to go, long-press to
  change), stored only on the phone; "Clear saved places" in settings
- Alternative routes: up to three route cards (Fastest, No tolls, Shortest, +N min, via road),
  selectable by card or by tapping a grey route on the map
- Report button (police, crash, hazard, traffic jam, road closed); reports appear on the map.
  They are stored in memory on the device only until the backend exists (Phase 2).

## Run it

Quickest on Windows: double-click `setup-windows.bat`. It installs Android Studio, the Android
SDK and an emulator, builds the app, and launches it with the virtual phone placed in Kuala
Lumpur. To run on a real phone instead, copy `apk/RoadPulse-debug.apk` to it and open it
(allow installs from unknown sources).

Manual route:

1. Install the latest Android Studio (the project uses Gradle 9.9 and Android Gradle plugin 9.5, which need a recent version) and open this folder.
2. Let Gradle sync, then run the `app` configuration on an emulator or phone (Android 8.0+).
3. Grant the location permission. On an emulator, set a location in Extended Controls > Location.

Command line: `gradlew.bat :app:assembleDebug` (APK lands in `app/build/outputs/apk/debug/`).

## Simulated drives and drive logs (debug builds only)

After calculating a route, the route card has a **Simulate** button. It runs navigation with a
simulated car instead of real GPS, so voice prompts, rerouting and arrival can be tested on the
emulator or at a desk:

- Drive the route at 50 km/h or at 90 km/h
- Take a wrong turn: leaves the route sideways at 30% of the trip, to test rerouting
- Bad GPS: 25 m position noise

Every debug navigation session, simulated or real, writes a CSV log with one row per GPS fix
(raw and route-matched position, offset, off-route state, distance to the next turn) and one row
per event (`drive_start`, `prompt`, `reroute_start`, `reroute_done`, `reroute_failed`,
`gps_lost`, `gps_restored`, `arrived`), ending with a `summary` row (fixes, reroutes, prompts, poor-signal fixes, largest
matched offset). Run `pull-drive-logs.bat` to copy the logs into `navlogs\`.

The logs contain precise locations: keep them local, delete them when done, and do not
commit them (`navlogs/` is in `.gitignore`). Release builds have neither the button nor the log.

## Screenshot tests

`OverlayScreenshotTest` renders the Explore, Preview and Driving panels on the JVM with
Robolectric and Roborazzi (no emulator) and writes PNGs to `app/build/outputs/roborazzi/`.

## Automatic checks (GitHub Actions)

`.github/workflows/android-ci.yml` runs on every push and pull request: unit tests, debug and
release builds, and a check that the release build is HTTPS-only. Test reports and the debug APK
are attached to each run. Plain HTTP is allowed only in debug builds, and only to a server on the
developer's machine (`app/src/debug/res/xml/network_security_config_debug.xml`).

## Field testing (Gate 1)

`docs/FIELD_TEST_PLAN.md` lists the Klang Valley test routes, safety rules, how to install the
debug app on a real phone, and the proposed Gate 1 targets. In debug builds the driving screen has
a **Flag issue** button that records problems with time and position, and the drive log records
battery level every 5 minutes. After driving: `pull-drive-logs.bat`, then `analyze-drives.bat`
(Python 3) writes `navlogs\report.md`.

## Configuration

Service URLs live in `gradle.properties` (`roadpulse.mapStyleUrl`, `roadpulse.routingUrl`,
`roadpulse.geocodingUrl`). The defaults point at free public servers that are fine for
development but not for production traffic. `backend/docker-compose.yml` starts your own
Valhalla routing server and a PostGIS database.

## Using your own server (debug builds)

With the Docker stack running (`backend/`, see `backend/README.md`), debug builds use it by
default: routing from your Valhalla (`http://10.0.2.2:8002`) and real community reports with live
updates from the API (`http://10.0.2.2:8080`). `10.0.2.2` is your computer as seen from the
emulator. Turn it off in Settings > "Use my laptop's server" to go back to public routing with
reports kept on the phone. Release builds never use these addresses.

End-to-end check of the app's reports code against a running backend (two simulated phones):
```
set ROADPULSE_BACKEND_URL=http://localhost:8080
gradlew testDebugUnitTest --tests com.roadpulse.app.data.LiveBackendTest
```
Add `ROADPULSE_MODERATOR_KEY` to also check moderator removals. Each run registers a few test devices; the API allows 10
registrations per hour per address, so for repeated runs raise `RateLimits__RegistrationsPerHour`
on the API container.

## Layout

    app/src/main/java/com/roadpulse/app/
      data/   models, Valhalla + Photon clients, polyline decoder, report repository
      nav/    RouteMatcher + RouteTracker (matching, off-route, prompts), NavigationSession,
              NavigationService, DeviceLocation, VoiceGuide, DriveStore (resume), SignalMonitor,
              PromptText, Narration (English/Malay/Arabic), VoiceSettings,
              DriveSimulator + DriveReplay + NavLog (debug)
      ui/     MapScreen (Compose + MapLibre), MapViewModel
    backend/  docker-compose (Valhalla, PostGIS) and database schema
    docs/     PLAN.md - architecture and roadmap; OFFLINE.md - behaviour without network/GPS;
              adr/ - architecture decision records; FIELD_TEST_PLAN.md - Gate 1 test drives

## Licensing notes

OpenStreetMap data is ODbL: the app must show "© OpenStreetMap contributors" attribution
(the map style includes it; keep it visible). No code, assets, or data from any other
navigation product are used, and none should be added.
